## Runtime corrections before release

Earlier simulator findings led to viewport-fitted Home framing, destination-specific standing/seated poses, the compact small-screen dock, camera controls beneath the wallet after onboarding, and removal of occluded world accessibility targets. The successful full guided run above includes those corrections. Existing campaign data and the previous clinic save were preserved; opening timings used a separate SE simulator with a fresh clinic save.

The first-cash double-tap tutorial interruption was fixed by restricting room selection until onboarding completes. Pointer-capture cleanup now listens at the actual capture target, preventing a completed button tap or pinch from leaving a stale finger that blocks subsequent controls. Mobile accessibility does not add a second direct action when the platform already synthesizes activation. Native virtual nodes can remain queryable when inactive, so collection assertions require a positive authoritative cash value and active geometry, not merely node existence.

Unity native accessibility requires reactivation whenever the screen reader is enabled, and layout-change notifications when nodes or frames change. Development builds accept the `CLINIC_ACCESSIBILITY_QA=1` launch environment variable to export the same nodes for native test inspection without enabling the operating system screen reader. The optional `-clinic-accessibility-qa` argument is also parsed, but did not propagate through the tested IL2CPP simulator launch; the environment variable was verified. This diagnostic override is absent from release builds. References: [Unity activation contract](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Accessibility.AssistiveSupport-activeHierarchy.html), [hierarchy update contract](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Accessibility.AccessibilityHierarchy.html), [diagnostic override](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Accessibility.AssistiveSupport-screenReaderStatusOverride.html).

The earlier corrected physical-phone run covers the 267-test snapshot with working-source SHA-256 `50163dac26d131be03f7d8c4b4cf76fa8b33951af749f3f63471e2e81214f788`. Its report, screenshots, save checks and limitations are in [the physical-device record](clinic-iphone-performance.md). Its local diagnostic app bundle was removed after installation and evidence collection to reclaim build space; the installed app and save remain. Runtime stdout was not captured, so the absence of collider errors is based on the two inspected frames. Final-source physical performance and thermal behavior remain **NOT ASSESSED**; simulator results do not replace that measurement.
