# Gravitile

A 3D idle world-builder for iOS. You tile a small spinning planet, and **the
mass of everything you build steers where its axis points** — which decides
which of your machines get sunlight.

| | |
|---|---|
| Platform | iOS 18+, iPhone and iPad |
| Stack | Swift 6, SwiftUI, RealityKit, StoreKit 2, GameKit, CoreHaptics |
| Engine | `OrbitKit` — pure Swift SPM package, fully deterministic |
| Project | Generated by XcodeGen — run `./Tools/generate.sh` |

## The mechanic

A freely rotating body that dissipates energy ends up spinning about its axis
of *maximum* moment of inertia. That is why a tossed phone tumbles flat, and
why concentrated mass on a spinning body migrates to the equator. Gravitile
makes that fact the game:

> **Mass drifts to the equator. Emptiness drifts to the poles.**

The equator is hot and lit; the poles are dark and frozen; every machine wants
a different temperature. So the real move is sculpting your mass distribution
to aim the climate bands at the machines that need them — and you watch it
happen, because the frost line visibly crawls across your world.

The **Wobble** gauge is the angle between where the world spins and where its
mass wants it to spin. High wobble means you are steering. Past 25°, the ground
starts to crack.

## Play

- **Build** — seven machines, each with an efficiency curve over temperature.
  Solar Arrays want light, Condensers want the frost line, Smelters want heat.
  **Ballast** produces nothing at all: it is pure weight, for steering.
- **Catch meteors** — they arrive every few minutes; tap before they burn up.
- **Collapse** — compress the world into its core for permanent Gravity, a
  bigger tiling (162 → 252 → 362 → 492 tiles) and richer crust.
- Production runs while the app is closed, capped at 8 hours plus Gravity.

Five OKLCH-derived color worlds live in the menu, and a theme repaints the
planet itself, not just the interface.

## Development

```bash
brew install xcodegen
./Tools/generate.sh                 # generates Gravitile.xcodeproj (+ scheme patch)
open Gravitile.xcodeproj
```

- Engine tests (fast, no simulator): `swift test --package-path GravitileKit`
- App + UI tests: run the `Gravitile` scheme's tests on an iPhone simulator
- Balance harness: `swift run --package-path GravitileKit -c release OrbitSim 20 10`
- Sounds are synthesized: `swift Tools/gensounds.swift Gravitile/Resources/Sounds`
- App icon is generated: `python3 Tools/genicon.py …/AppIcon.appiconset/icon-1024.png`

Debug hooks (simulator): launch argument `-gravitile-reset` wipes saved state;
`-gravitile-demo` starts a stocked mid-game world, which is what the store
screenshots are shot from.

## Architecture

`OrbitKit` holds the whole simulation and imports no UI framework:

- **Tiling** — a Goldberg polyhedron (subdivided icosahedron, then its dual).
  Vertices are identified canonically rather than by float comparison, so
  shared corners are bit-identical and the dual has no seams.
- **Axis** — the mass-distribution covariance, a Jacobi eigen-decomposition,
  and settling toward the minimum-eigenvalue axis. Degeneracy is the *common*
  case (one pile of mass makes every perpendicular axis equally good), so the
  world takes the shortest path within the degenerate eigenspace.
- **Climate** — the standard rotation-averaged insolation formula, which means
  aiming the axis at the star buys a permanently lit cap and a permanently
  frozen hemisphere.

Every sum over the world walks tiles in index order rather than dictionary
order: hash layout was leaking into the last bits of the spin axis and breaking
replay determinism.

The app layer renders that state with RealityKit and never writes back to it.
Tile picking is analytic ray–sphere math against our own camera rig, so it is
testable without a running scene.
